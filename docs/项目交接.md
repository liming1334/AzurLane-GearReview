## 一、项目是什么

**碧蓝航线装备性能排行工具**：抓取碧蓝航线 WIKI 的装备数据，按伤害公式算 77 秒窗口累计伤害并排名，
带图标、卡片式详情、白天/夜间主题、毛玻璃按钮、自定义背景。

- 技术栈：Python 3.12 + tkinter + Pillow，PyInstaller 打包
- 工作目录：`G:\azur lane`
- 交付物：`dist\碧蓝装备排行\碧蓝装备排行.exe`（onedir，约 49.8 MB，整个文件夹一起移动）
- 仓库：已 `git init`，5 次提交（`508a1a1` 初版、`e1e11ae` 毛玻璃与数据修正、
  `f3509fa` 交接文档、`ab169af` 修复 `_rate_levels`、`ac7a307` 回归测试），MIT 协议
- 测试：`tests/test_core.py`，33 条用例，`python -m unittest discover -s tests -v` 全绿

## 四、评分规则（当前口径）

### 通用
```
属性系数 = 1 + 属性值/100 × 属性效率
增伤乘区 = (1+增伤) × (1+debuff) × (1+等级差×0.02) × 暴击倍率
```

### 舰炮 / 导弹 / 鱼雷 / 防空炮（77 秒）
```
开火间隔 = √(200/(装填值+100)) × 装填 + 开火动画
开火次数 = floor(77 / 间隔) + 1        # 首轮 t=0
单轮伤害 = 属性系数 × 单发 × 修正比例 × 对甲效率 × 弹数 × 增伤乘区
评分     = 单轮伤害 × 开火次数
```
动画：驱逐 0.26 / 轻巡 0.28 / 重巡 0.30 / 战列跨射 0 / 鱼雷 0.20 / 防空 0。
防空炮无修正比例、无对甲，只出「对空」。

### 舰载机（77 秒，按架次）
```
单架次对空 = Σ(机枪单发 × 数量) × (1 + 航空/100 × 效率)
单架次对甲 = Σ(炸弹/鱼雷单发 × 数量 × 对甲%) × (1 + 航空/100 × 效率 × 武器效率)
架次       = floor(77 / √(200/(装填值+100)) × 标准射速) + 1   # 飞机无开火动画
评分       = 单架次 × 架次
```
武器属性效率：航空炸弹 80%，火箭弹（HVAR/RP-3/RS-82/S-21/Wfr.Gr/TinyTim）100%，鱼雷/机枪 100%。

### 强化档位（两步）
1. **按装备自身上限截断**：`max_level` = 页面所有 `强化+N` 字段的最大 N；
   一个都没有时按稀有度（白 3 / 蓝 6 / 紫 10 / 金 13 / 彩 13）
2. 伤害、射速、伤害补正**各自**取「不高于目标档的最高已有档」

> 这一步是第 9 轮修的 bug：F4F野猫T1 白色只能 +3，武器库却有 +0~+13，旧代码取了 +13 的 68，
> 正确是 +3 的 33。现在详情会红字提示「该装备最高 +3，已按 +3 计算」。

### 不计入
燃烧/进水、命中率、散布、防空减伤；暴击默认 1。

## 五、界面要点

- **主题**：`THEMES` 字典（day/night），所有静态控件经 `_label/_frame/_button` 登记，切换时统一刷新；
  夜间输入框等「框」按用户要求用 **#305973**
- **坑**：clam 自带 `TCombobox` 的 `readonly` 状态映射（浅灰），必须 `style.map()` 覆盖
- **毛玻璃按钮**：截取按钮位置的背景 → 模糊 10px → 按 40~62% 混容器色 → 8px 圆角蒙版 → 1px 高光描边 →
  `compound="center"`；主题/背景/缩放后重生成
- **背景图**：`data/background.json` + 复制到数据目录；cover 裁切 + 高斯模糊 + 主题叠色；
  详情卡片用 canvas window 挂载，让壁纸从卡片缝隙透出
- **详情**：卡片 = 头部(图标/名称/标签) → 伤害评分(数字牌+口径+计算过程) → 基础数据(按强化档位取值)
  → 舰载挂载 → 技能 → 完整属性
- **输出测试**：任意时长，默认 77 秒，舰炮按轮次、舰载机按架次
- 已移除：Wiki 跳转按钮、双击跳转、CSV 的 Wiki 列

## 八、已知问题 / 待办

> 第 10 轮用户明确决定：**待办 1、2 本轮都不动**（射速口径「先不动，做别的」，
> max_level「本轮先不动」）。两项都仍需口径拍板，不要自行改。

1. **max_level 依赖页面字段**：若某装备 wiki 少写 +13 字段但游戏可到 +13，会被低估。
   第 10 轮审计：**31 件**「页面字段低于稀有度上限」（26 金 max=10、2 彩 max=10、若干 11）。
   同时有反例：蓝色页面列到 +13（6 件）、紫色列到 +13（5 件），属于被高估。
   → 因为上下两个方向页面都不可靠（白色 F4F 列了 +13 但只能 +3），
   只靠 `min(页面, 稀有度)` 修不了低估，**只能白名单**。
2. 舰载机机枪**不乘射速**，对空是「单发 × 数量」；若要更精确可改成 DPS 口径。
   第 10 轮已把射速解析入库（`mounts[].rate`，{档位: 发/分}），评分端未使用。
   量化影响：161 架带机枪的飞机 **148 架名次会变**，瑞云T1 升 41 位、G.50箭式 升 32 位，
   Fi-167 降 34 位（高射速机枪上浮、低速鱼雷机下沉）。
3. **`RARITY_MAX_LEVEL` 与实际档位不符**（第 10 轮由测试发现）：
   表里 紫色=10 / 蓝色=6，但数据中 紫色 +11 有 93 件、蓝色 +7 有 62 件。
   当前没出事是因为**没有任何装备 `max_level=0`**（674 件全都有页面字段），
   兜底分支实际是死代码；一旦某页缺字段就会按错误的档位算。改这张表前先确认游戏真实上限。
4. 稀有度兜底的紫色档位取 +10（同上，属兜底分支，实际不触发）
5. numpy/pandas 被 Pillow 依赖分析带入，已用 `--exclude-module` 排除（别删，否则包体 77MB）
6. 设备与特殊兵装已按要求剔除；若以后要加回，需扩展 EXCLUDED_CATEGORIES 与评分分支
